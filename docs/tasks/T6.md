## 1. Rename `attempt` → `deliveryCount` (it counts pickups, like an SQS receive count)
Everywhere: column, `ScanSchema`, repository, pool, API response, tests. Config `maxAttempts` → `maxDeliveries`
(env `MAX_DELIVERIES`). `ScanTransition.resetAttempts` → `resetDeliveries`, `refundAttempt` → `refundDelivery`.

## 2. DLQ check at claim time (bug: a scan that keeps crashing workers is never failed)
`claimNextScan(workerId, now, leaseMs, maxDeliveries)`: inside the same transaction, before selecting, move every scan
in a running status with `leaseExpiresAt < now` and `deliveryCount >= maxDeliveries` to `failed` with
`error = 'Scan was abandoned by workers <n> times without progress'` (clear lease fields, set `finishedAt`). Then claim
as before. Test: a scan reclaimed after `maxDeliveries` expired leases ends `failed`, not claimed.

## 3. Progress resets the count
`advanceCheckpoint` also sets `deliveryCount = 1` (the current delivery). `deliveryCount` then means "deliveries in a row
without progress". The pool re-reads the scan (`getScan`) before deciding retry vs `failed`, so it uses the fresh count.
Backoff = `retryBaseMs × 2^(deliveryCount - 1)`. Test: a scan that advanced a page after 2 crashes is retried, not failed.

## 4. `transitionScan` returns `'duplicate_active'`
When the update hits the unique active-repo index (resume while the repo has another active scan), the repository
catches only that SQLite constraint error and returns `'duplicate_active'`. The service switches on it; no SQLite
codes in `scanService.ts`.

## 5. Clone directory per claim (Codex P1)
Clone path = `join(config.clonesDir, \`${scanId}-${leaseToken}\`)`. A stalled worker that lost its lease must never
delete the new owner's clone. Use that exact path for every git call and for cleanup. Test: two claims of the same scan
get different directories, and cleaning up the first leaves the second.

## 6. No argument spreading of findings (Codex P2)
`scanRunner.ts:162`: replace `push(...findings)` with a plain loop. Test with ~150,000 findings from one fake commit.

## 7. Rollback test (Codex P3)
Make a later finding insert fail inside the page transaction (e.g. a SQLite `BEFORE INSERT` trigger on `findings` that
raises for a marker value) and assert the checkpoint and every finding from that page roll back together.

## 8. Docs
Update `docs/ERD.md` (column name) and `docs/DESIGN_DECISIONS.md` section 9 to describe: delivery count counted at
claim (crashes can't report), `failed` = the DLQ, limit checked at claim and on reported failures, reset on progress, on
`resume` (redrive) and refunded on graceful shutdown. You may edit those two docs for this.

**How I did it:**
- `src/config.ts`, `src/domain/scan.ts`, `src/db/schema.ts`, `src/api/apiSchemas.ts`: `maxDeliveries` / `MAX_DELIVERIES`,
  `deliveryCount` column, field and API response field.
- `src/db/scanRepository.ts`: `claimNextScan(workerId, now, leaseMs, maxDeliveries)` first runs one `UPDATE` that moves
  running scans with an expired lease and `deliveryCount >= maxDeliveries` to `failed` (lease cleared, `finishedAt`
  set), in the same `BEGIN IMMEDIATE` transaction as the claim. `advanceCheckpoint` sets `deliveryCount = 1`.
  `transitionScan` returns `TransitionResult` and catches only `SQLITE_CONSTRAINT_UNIQUE` (2067) as `'duplicate_active'`.
  `resetDeliveries` / `refundDelivery` renamed. Error text comes from exported `toAbandonedScanError(n)`.
- `src/services/scanService.ts`: `requeueScan` is a `switch` on the result; no SQLite code or try/catch left.
- `src/scanner/scanRunner.ts`: `getCloneDir(config, scanId, leaseToken)` → `<clonesDir>/<scanId>-<leaseToken>`, used
  for clone, every git call and (in the pool) cleanup. Findings are appended with a plain loop.
- `src/worker/workerPool.ts`: passes `maxDeliveries` to the claim; `applyOutcome` re-reads the scan's `deliveryCount`
  before deciding retry vs `failed`; backoff = `retryBaseMs × 2^(deliveryCount - 1)`. The transition still uses the
  lease token we claimed with, so a re-read never lets us overwrite another worker.

**Decisions / tradeoffs:**
- The abandoned error message uses `maxDeliveries` as `<n>` (equal to `deliveryCount` unless the config was lowered
  while scans were in flight); this keeps the message a TS-side constant tests can assert against.
- `readDeliveryCount` throws if the scan is missing, like `readScan` in the service: scans are never deleted, and it
  avoids a non-null assertion.
- `scanRunner` (cloning → scanning) and `stopQueuedScan` now treat any non-`'applied'` result as lost / invalid
  state, since the union has three values.
- `ResumeScanOutcome` keeps its `{ kind: 'conflict' }` name so `scanRoutes.ts` did not change.
- Also fixed the `attempt` mentions in DESIGN_DECISIONS sections 7 (table), 10, 11 and 18, plus the clone-dir race row.
- **Not updated (outside my files):** `docs/ARCHITECTURE.md` still says `attempt` / `MAX_ATTEMPTS` (lines ~61, 97–98,
  119, 138, 144, 146, 189) and the clone path `DATA_DIR/clones/<scanId>`; README / compose (T5) should use
