# T3 — Scan runner and worker pool

**Goal:** The part that does the work and survives failure: a runner that takes one claimed scan from its checkpoint to
the end, and a pool that claims scans, keeps leases alive, obeys stop requests, maps outcomes to state transitions,
retries with backoff, cleans up clones and shuts down gracefully. Target: about 35 minutes.
**Depends on:** T1 (merged). T2 is built in parallel: code against the `GitClient` interface in `src/git/gitTypes.ts`
and the `detectLeaks(line): DetectedLeak[]` signature (pass it in as a dependency), and test with a fake `GitClient`.

## Contracts

### `src/scanner/scanRunner.ts`
```ts
export interface ScanRunnerDeps {
  config: Config; logger: Logger; db: DatabaseSync;
  scanRepository: ScanRepository; findingRepository: FindingRepository;
  gitClient: GitClient; detectLeaks: (line: string) => DetectedLeak[];
}
export type ScanOutcome =
  | { kind: 'completed' }
  | { kind: 'stopped'; status: 'cloning' | 'scanning' }
  | { kind: 'lost' }                                   // our lease/token is no longer valid
  | { kind: 'failed'; status: 'cloning' | 'scanning'; error: string; isRetryable: boolean };
export function createScanRunner(deps: ScanRunnerDeps): { runScan(scan: Scan, control: RunControl): Promise<ScanOutcome> };
export interface RunControl { signal: AbortSignal; shouldStop(): boolean }
```
`runScan` receives a scan the pool just claimed (status `cloning`, its `leaseToken`). Steps:
1. Clone dir = `join(config.clonesDir, scan.id)`. Remove it if present, then `cloneMirror`.
2. First run (`refTips` null): `readRefTips`, `listCommitsNewestFirst`, `saveRefTips(…, total)`.
   Resume (`refTips` set): `hasAllCommits(Object.values(refTips))` — false → `failed`, not retryable,
   "history changed since the scan started; start a new scan". Then `listCommitsNewestFirst(refTips)`. If
   `scannedCommits > 0` and the commit at index `scannedCommits - 1` isn't `lastScannedSha` → same failure.
   Any fenced write returning false → `lost`.
3. `transitionScan(cloning → scanning)`; `'conflict'` → `lost`.
4. For each page of `config.batchSize` commits from `scannedCommits`: if `shouldStop()` → `stopped`. Stream the page's
   diffs, run `detectLeaks` on every added line, build `NewFinding`s (copy commit fields). Then
   `runInTransaction(db, …)`: `advanceCheckpoint` first; if it returns false throw a `LeaseLostError` (rolls the
   transaction back, turned into `lost`); then `insertFindings`.
5. Return `completed` (the pool writes the transition).
- `GitCommandError` → `failed` with its `isRetryable`. Abort (signal) → the pool decides (it knows why it aborted):
  return `lost` when the signal reason is lost, otherwise let it map to a release. Unknown errors → `failed`,
  retryable (the attempt cap stops loops).

### `src/worker/workerPool.ts`
`createWorkerPool(deps: WorkerPoolDeps): WorkerPool` with `start(): Promise<void>` and `stop(): Promise<void>`.
`WorkerPoolDeps = { config, logger, scanRepository, scanRunner, now?: () => Date }`.
- `start()`: wipe `config.clonesDir` (leftovers from a crash), then start `config.workerConcurrency` slot loops.
- Slot loop: `claimNextScan(workerId, now, leaseMs)` where `workerId = ${hostname}-${pid}-${slotIndex}`. Nothing →
  wait `pollMs` (cancellable by `stop()`). Got one → run it with a heartbeat.
- Heartbeat every `leaseMs / 3`: `renewLease`. `lost` → abort the run (reason `lost`). `stopRequested` → make
  `shouldStop()` true.
- Map the outcome (from = the status the runner reports, `leaseToken` = the claimed token):
  | Outcome | Transition |
  |---|---|
  | completed | scanning → completed |
  | stopped | status → stopped |
  | failed, retryable, `attempt < maxAttempts` | status → queued with `runAfter = now + retryBaseMs × 2^(attempt-1)`, `error` |
  | failed, otherwise | status → failed with `error` |
  | lost | no write at all |
  | aborted by `stop()` (shutdown) | status → queued with `refundAttempt: true` |
- Always delete the clone dir when the run ends, whatever the outcome (in `finally`).
- `stop()`: stop claiming, abort running scans (reason `shutdown`), wait for every slot to finish its release.
- Log with structured fields (`scanId`, `attempt`, `outcome`); never log the token.

## Tests (in-memory SQLite + `test/helpers/fakeGitClient.ts`, a scripted `GitClient`)
- Runner, happy path: 5 commits, batch size 2 → 3 pages, findings stored, `scannedCommits = 5`, status `scanning`.
- Runner, resume: start with `scannedCommits = 2` and matching `lastScannedSha` → only commits 3–5 are streamed.
- Runner, crash mid-page: fake git throws on page 2 → page 1's checkpoint and findings are kept, nothing from page 2.
- Runner, history changed: `hasAllCommits` false → failed, not retryable.
- Runner, lost lease: bump the scan's `leaseToken` in the DB before a page → outcome `lost`, no findings from that page.
- Pool: a retryable failure re-queues with `runAfter`; after `maxAttempts` it ends `failed`.
- Pool: `stop()` releases a running scan to `queued` without using an attempt.
Use small `leaseMs`/`pollMs` from `createTestConfig`; no real sleeps longer than ~100 ms.

## TL;DR (the worker fills this in when done)
**Asked to do:** Build the scan runner (one claimed scan from its checkpoint to the end, page by page) and the worker
pool (claim, heartbeat, stop flag, outcome → transition, retry with backoff, clone cleanup, graceful shutdown).

**How I did it:**
- `src/scanner/scanRunner.ts`: `runScan` = prepare the commit list (wipe + clone, then freeze ref tips on the first run
  or verify tips and the checkpoint SHA on resume) → `cloning → scanning` → `scanPages`. Each page: check
  `shouldStop()`, `signal.throwIfAborted()`, stream diffs, build findings, then one transaction (checkpoint first,
  `LeaseLostError` rolls it back). One `catch` turns errors into an outcome.
- `src/worker/workerPool.ts`: one slot loop per `workerConcurrency`; each run gets
  `AbortSignal.any([shutdown, leaseLost])`, so `signal.reason` tells the pool and the runner why it aborted.
  `toTransition` is a `switch` on `outcome.kind` that mirrors the brief's table; the clone dir is removed in `finally`.
- `test/helpers/fakeGitClient.ts`: scripted `GitClient` with `onClone` / `onStreamPage` hooks (throw, block until
  abort, or bump the DB token) and a record of every streamed page.
- Tests: 7 runner tests (the 5 from the brief + checkpoint SHA moved + stop between pages), 3 pool tests (complete +
  clone dir deleted, retry with backoff then `failed`, `stop()` releases with the attempt refunded).

**Decisions / tradeoffs:**
- Exported from the runner: `LEASE_LOST_REASON`, `HISTORY_CHANGED_ERROR` (for tests/API) and `getCloneDir` (the pool
  needs the same path to delete it). The pool exports `SHUTDOWN_REASON`.
- Shutdown only overrides a `failed` outcome (the abort is what made it fail). If the run still finished as
  `completed`/`stopped`, that result is written.
- A history-changed failure reports status `cloning` (we have not moved to `scanning` yet).
- No try/catch around DB calls in the slot loop or heartbeat: a DB error crashes the process, and the lease expiry +
  reclaim recovers the scan. Catching it would be a guard beyond the spec.
- The pool tests use the real runner with the fake git client (no stubbed runner) and an injected clock for backoff.

**How to verify:** `npm run check`; or `npx vitest run test/scanner/scanRunner.test.ts test/worker`.
