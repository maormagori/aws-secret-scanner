## Contracts

Names below are the contract: later tasks import them exactly. Use camelCase (normal TypeScript naming).

### `src/config.ts`
`loadConfig(env: NodeJS.ProcessEnv): Config` — Zod schema `ConfigSchema`, `Config = z.infer<…>`. Fields and defaults:
`role` (`'api' | 'worker' | 'all'`, default `'all'`), `port` (3000), `dataDir` (`'./data'`), `githubToken` (optional),
`workerConcurrency` (3), `leaseMs` (30000), `pollMs` (1000), `batchSize` (200), `maxAttempts` (3), `retryBaseMs` (5000),
`cloneTimeoutMs` (600000), `bigFileThreshold` (`'50m'`), `logLevel` (`'info'`), `clonesDir` (`'./data/clones'`;
workers wipe it at start, so it is separate from the shared database), `databaseFile` (`'./data/scanner.db'`). Env names are the upper snake case of
each field (`WORKER_CONCURRENCY`, …). Numbers are coerced from strings. Invalid env throws with the field name.
Also add `test/helpers/testConfig.ts` exporting `createTestConfig(overrides?: Partial<Config>): Config` so tests never
retype config values.

### `src/logger.ts`
`createLogger(config: Config): Logger` using pino (already a dependency). Export the `Logger` type.

### `src/domain/scan.ts`
- `ScanStatusSchema = z.enum(['queued','cloning','scanning','completed','failed','stopped'])`, `ScanStatus` type.
- `ACTIVE_SCAN_STATUSES` (`queued`, `cloning`, `scanning`) and `RUNNING_SCAN_STATUSES` (`cloning`, `scanning`) as
  constants built from the schema's values.
- `RefTipsSchema = z.record(z.string(), z.string())` (ref name → commit SHA).
- `ScanSchema` with exactly the columns in ARCHITECTURE.md → Data model → scans. Timestamps are ISO strings;
  `refTips` is `RefTips | null`; `leaseOwner`, `leaseExpiresAt`, `runAfter`, `error`, `finishedAt`, `lastScannedSha`
  nullable; `stopRequested` boolean; `totalCommits` nullable number; `scannedCommits` number.

### `src/domain/finding.ts`
- `LeakTypeSchema = z.enum(['aws_access_key_id','aws_secret_access_key'])`.
- `FindingSchema` with the columns in ARCHITECTURE.md → Data model → findings. `NewFindingSchema = FindingSchema.omit({ id: true })`.

### `src/domain/repoUrl.ts`
`parseRepoUrl(input: string): { kind: 'valid'; repoUrl: string } | { kind: 'invalid'; reason: string }`.
Accepts `owner/repo`, `https://github.com/owner/repo`, with or without `.git` or a trailing slash. Returns the normalized
form `https://github.com/owner/repo` (owner and repo lowercased). Anything else (other hosts, extra path parts, `..`,
whitespace, empty) is invalid. Owner/repo characters: letters, digits, `-`, `_`, `.`.

### `src/domain/scanStateMachine.ts`
`SCAN_TRANSITIONS: Record<ScanStatus, readonly ScanStatus[]>`, exactly the diagram in ARCHITECTURE.md, plus
`cloning → cloning` and `scanning → cloning` (a reclaim after an expired lease restarts at cloning).
`canTransition(from: ScanStatus, to: ScanStatus): boolean`.

### `src/db/database.ts`
- `openDatabase(filePath: string): DatabaseSync` (`node:sqlite`). `':memory:'` must work for tests. Sets
  `journal_mode = WAL` (skip for `:memory:`), `busy_timeout = 5000`, `foreign_keys = ON`, and creates both tables and
  indexes if missing (plain `CREATE TABLE IF NOT EXISTS`; no migration framework).
- Indexes: unique partial index on `scans(repoUrl) WHERE status IN ('queued','cloning','scanning')`; unique index on
  `findings(scanId, commitSha, filePath, lineNumber, leakValue)`; index on `scans(status, runAfter)`.
- `runInTransaction<T>(db: DatabaseSync, work: () => T): T` — `BEGIN IMMEDIATE`, commit on return, rollback and
  rethrow on throw.

### `src/db/scanRepository.ts` — `createScanRepository(db: DatabaseSync): ScanRepository`
Every method maps rows to `Scan` via `ScanSchema.parse` (the parsing boundary). `now` is passed in (a `Date`) so tests
control time.
- `createScan(repoUrl, now): { kind: 'created'; scan: Scan } | { kind: 'existing'; scan: Scan }` — inserts `queued`;
  on the unique-index violation returns the active scan for that repo.
- `getScan(scanId): Scan | undefined`, `listScans(): Scan[]` (newest first).
- `claimNextScan(workerId, now, leaseMs): Scan | undefined` — inside `runInTransaction`: pick the oldest scan that is
  (`queued` and (`runAfter` null or `<= now`) and not `stopRequested`) or (in a running status with
  `leaseExpiresAt < now`); set `status = 'cloning'`, `leaseOwner`, `leaseExpiresAt = now + leaseMs`,
  `leaseToken = leaseToken + 1`, `attempt = attempt + 1`, `runAfter = null`. Return the updated scan.
- `renewLease(scanId, leaseToken, now, leaseMs): { kind: 'renewed'; stopRequested: boolean } | { kind: 'lost' }` —
  fenced by `leaseToken` and a running status.
- `transitionScan(change: ScanTransition): 'applied' | 'conflict'` where `ScanTransition` = `{ scanId, from, to,
  leaseToken: number | null, now, error?: string | null, runAfter?: string | null, resetAttempts?: boolean, refundAttempt?: boolean }`.
  Throws if `canTransition(from, to)` is false (a programming error). Runs one `UPDATE … WHERE id = ? AND status = ?`
  plus `AND leaseToken = ?` when `leaseToken` is not null. Leaving a running status clears the lease fields; entering
  `completed`/`failed`/`stopped` sets `finishedAt`; entering `queued` clears `finishedAt` and `stopRequested`;
  `resetAttempts` sets `attempt = 0`; `refundAttempt` sets `attempt = max(attempt - 1, 0)` (graceful shutdown
  releases scans with it so a deploy doesn't use up retries). `0` rows → `'conflict'`.
- `saveRefTips(scanId, leaseToken, refTips, totalCommits, now): boolean` — fenced; true when applied.
- `advanceCheckpoint(scanId, leaseToken, scannedCommits, lastScannedSha, now): boolean` — fenced; true when applied.
- `requestStop(scanId, now): boolean` — sets `stopRequested = 1` on a scan in a running status.

### `src/db/findingRepository.ts` — `createFindingRepository(db: DatabaseSync): FindingRepository`
- `insertFindings(findings: NewFinding[]): void` — `INSERT OR IGNORE`, one prepared statement. Callers wrap it with
  `advanceCheckpoint` in `runInTransaction`.
- `listFindings(scanId, afterId: number | null, limit): Finding[]` — `WHERE scanId = ? AND id > ? ORDER BY id LIMIT ?`.

## TL;DR (the worker fills this in when done)
**Asked to do:** Lay the foundation: config, logger, domain schemas, the scan state machine, SQLite with both tables,
both repositories and the git contracts, with tests for the domain and the repositories.

**How I did it:**
- `src/config.ts`: Zod `ConfigSchema` with defaults, including the added `clonesDir` and `databaseFile`. `loadConfig`
  maps each env var to its field explicitly and throws with `z.prettifyError` (which names the field).
- `src/domain/*`: the schemas, `ACTIVE_`/`RUNNING_`/`FINISHED_SCAN_STATUSES` built with `ScanStatusSchema.extract`,
  `parseRepoUrl` (strip prefix, `/`, `.git`, then split into exactly two valid names), and `SCAN_TRANSITIONS`.
- `src/db/schema.ts` holds the DDL; `database.ts` opens the DB (WAL unless `:memory:`) and has `runInTransaction`
  (`BEGIN IMMEDIATE`). `scanRow.ts` turns a row into a `Scan` (JSON `refTips`, 0/1 `stopRequested`).
- `src/db/scanRepository.ts`: prepared statements using named parameters. Status values come from the schema
  constants, never typed as literals. `transitionScan` builds its `SET` list from the change, including
  `refundAttempt` → `attempt = MAX(attempt - 1, 0)`. `src/db/findingRepository.ts`: `INSERT OR IGNORE` plus a keyset
  page.
- `src/git/gitTypes.ts`: the contract types and `GitCommandError`.

**Decisions / tradeoffs:**
- `createScan` runs `INSERT OR IGNORE` inside `BEGIN IMMEDIATE` and then reads the active scan. The unique index still
  decides who wins. The transaction just keeps that scan from finishing between the insert and the read.
- Fenced writes (`renewLease`, `saveRefTips`, `advanceCheckpoint`) check `leaseToken` *and* a running status. A worker
  that has already released its scan to `queued` can't write to it until the next claim.
- Added `FINISHED_SCAN_STATUSES` (completed/failed/stopped): `transitionScan` uses it for `finishedAt`, and T4 can use
  it for the 409 check.
- The status constants are typed `readonly ScanStatus[]` so `.includes(status)` works without casts.
- `toSqlList` interpolates our own constant status lists into SQL (never user input), so one constant drives both the
  partial index and the queries.
- `committedAt` accepts ISO strings with an offset (git's `%cI` gives `+02:00`).
- There is no `test/config` test, because the brief doesn't allow that folder. `createTestConfig` exercises
  `loadConfig({})` defaults.

**How to verify:** `npm run check` (typecheck + lint + 56 tests). Repository tests: `npx vitest run test/db`.
