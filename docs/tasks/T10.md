# T10 — Demo dashboard (observability, outside the app)

**Goal:** A tiny local dashboard for demoing the scanner: see the containers' logs and the database state (scans,
leases, checkpoints, findings) update live, and start/stop/resume scans. It is a demo tool, not part of the app.
Hard deadline: working and reported by **16:03**.
**May change:** only a new folder `demo-ui/` and one line in `README.md` (how to start it). Do NOT touch `src/`,
`test/`, `package.json`, `package-lock.json`, `Dockerfile` or `docker-compose.yml`. No new npm packages. Do not commit.

## Shape
- `demo-ui/compose.demo.yml`: a compose override that adds one service, `dashboard`, used as
  `API_PORT=3100 docker compose -f docker-compose.yml -f demo-ui/compose.demo.yml up --build`.
  - Image `node:24-alpine`, runs `node /demo-ui/server.mjs`, mounts `./demo-ui` read-only, the existing
    `scanner-data` volume **read-only** at `/data`, and `/var/run/docker.sock` (read-only) for logs. Port
    `${DASHBOARD_PORT:-3200}:3200`. Env: `DATABASE_FILE=/data/scanner.db`, `API_URL=http://api:3000`.
- `demo-ui/server.mjs`: plain Node (`node:http`, `node:sqlite` opened **read-only**, no packages). Endpoints:
  - `GET /` → `index.html`.
  - `GET /state` → JSON: all scans (every column, including lease owner/expiry, leaseToken, deliveryCount,
    scannedCommits/totalCommits, runAfter, stopRequested, error), findings count per scan, the last 20 findings.
  - `GET /logs` → last ~200 log lines of every container in the compose project, read from the Docker Engine API over
    the socket (`/containers/json?filters=…label com.docker.compose.project…`, then `/containers/<id>/logs?stdout=1
    &stderr=1&tail=200&timestamps=1`; strip the 8-byte stream frame headers). Tag each line with the container name.
  - `POST /scans`, `POST /scans/:id/stop`, `POST /scans/:id/resume` → proxied to `API_URL` (the app's own API, so
    all writes go through the app).
- `demo-ui/index.html`: one page, vanilla JS, polls `/state` and `/logs` every second. Sections: a form to start a
  scan; a scans table (status colour-coded, progress bar, lease owner + seconds left, token, deliveries, stop/resume
  buttons); recent findings (time, commit, committer, file:line, type, value); a logs panel with one column or filter
  per container (`api`, each worker) where pino JSON lines are shown compactly (time, level, msg, scanId). Plain CSS,
  readable on a laptop screen.
- `demo-ui/README.md`: 5 lines on how to start it and what it shows.
