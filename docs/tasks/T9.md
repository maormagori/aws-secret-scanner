# T9 — One blob fetch per page instead of per commit

**Goal:** In a blobless clone, `git log -p` fetches missing file contents from GitHub about once per commit (measured: 12
fetches for 13 non-merge commits on the fixture). Prefetch every blob a page needs in **one** request before streaming
its diffs, so a page of 200 commits costs one network round trip. Target: about 25 minutes.
**Depends on:** T2, T7 (working tree). Read `CLAUDE.md`, `docs/tasks/T2.md`, `docs/tasks/T7.md` (TL;DRs),
`src/git/gitClient.ts`, `src/git/gitProcess.ts`.
**May change:** `src/git/gitClient.ts`, a new `src/git/blobPrefetch.ts`, `test/git/*`. Nothing else. The `GitClient`
interface in `gitTypes.ts` does not change: `streamCommitDiffs` does the prefetch itself. Do not commit.
**Verify:** `npm run check`, plus the tests below.

## How
1. **List the blobs the page needs** (local, no network: commits and trees are already in the clone):
   `git diff-tree -r --root --no-renames --no-commit-id --stdin` with the page's SHAs on stdin. Each output line is
   `:<oldMode> <newMode> <oldSha> <newSha> <status>\t<path>`. Collect every old and new blob SHA that is not all zeros
   (git needs both sides to build the diff). Skip submodule entries (mode `160000`). Merge commits print nothing
   without `-m`, which matches what `git log -p` scans.
2. **Fetch them in one request**, the same way git's own lazy fetch does:
   `git -c fetch.negotiationAlgorithm=noop fetch origin --no-tags --no-write-fetch-head --recurse-submodules=no
   --filter=blob:none --stdin` with the blob SHAs on stdin. Use the same auth header and the same error classification
   (retryable vs not) as the clone. Already-present blobs: skip them first with
   `git cat-file --batch-check` (missing lines only) under `GIT_NO_LAZY_FETCH=1`, so a page whose blobs are all local
   makes no request. No blobs needed → no request.
3. Then run `git log -p` as today. Run it with `GIT_NO_LAZY_FETCH=1` is NOT wanted (a blob we missed must still be
   fetched rather than fail); keep lazy fetch as the fallback.
4. Check whether the existing `git log` command passes the auth header (lazy fetches of a private repo need it). If it
   doesn't, add it, and say so in the TL;DR.

## Tests
- A local "remote": `git init --bare` with `uploadpack.allowFilter=true` and `uploadpack.allowAnySHA1InWant=true`, push
  a few commits (one adds a fake AWS key), blobless mirror clone it over `file://`. Then `streamCommitDiffs` for all
  commits: findings' lines are correct, and with `GIT_TRACE` (or by counting fetch processes some other reliable way)
  exactly **one** fetch happens for the page, not one per commit.
- Unit test for parsing `diff-tree` lines (zeros skipped, submodules skipped, both sides collected).

## TL;DR (the worker fills this in when done)
**Asked to do:** Make `streamCommitDiffs` fetch every missing blob of a page in one request before `git log -p`,
instead of git's lazy fetch running about once per commit in a blobless clone.

**How I did it:**
- `src/git/blobPrefetch.ts` (new, pure): `listBlobShas` reads `diff-tree -r` lines and returns each old and new blob
  SHA once, skipping all-zero SHAs and submodules (`160000`); `listMissingShas` reads `cat-file --batch-check` lines.
- `src/git/gitClient.ts`: `streamCommitDiffs` first runs `prefetchBlobs`: `git diff-tree -r --root --no-renames
  --no-commit-id --stdin` (local) → `cat-file --batch-check` under `GIT_NO_LAZY_FETCH=1` → if anything is missing, one
  `git -c fetch.negotiationAlgorithm=noop fetch origin --no-tags --no-write-fetch-head --recurse-submodules=no
  --filter=blob:none --stdin` with the missing SHAs. Then `git log -p` runs as before, lazy fetch still on.
- The fetch goes through the same `streamGitLines`, so it gets the same auth header, redaction and retryable /
  non-retryable error mapping as the clone.
- `hasAllCommits` now reuses the same `listMissingObjects` helper (same `cat-file` command it ran before).

**Decisions / tradeoffs:**
- Works as described over `file://` (git 2.52): with `uploadpack.allowAnySHA1InWant=true` on the remote, one fetch
  with blob SHAs on stdin downloads them all (GIT_TRACE shows one `git fetch` built-in, one `upload-pack`, one
  `index-pack --promisor`; `cat-file` then reports all of them present). GitHub allows fetching by SHA already.
- Auth on `git log` (step 4): it already had the header. Every command goes through `streamGitLines`, which prepends
  `http.extraHeader` (T2), and the lazy-fetch subprocess inherits `-c` options via `GIT_CONFIG_PARAMETERS`. No change.
- The fetch uses the page's abort signal only, no separate timeout (the lazy fetch it replaces had none either).
- A page whose blobs are all local, or that has no blobs, makes no request (only the local diff-tree / cat-file).
- `gitClient.ts` grew to ~200 lines (over the ~150 aim); the brief allows only `blobPrefetch.ts` as a new file, and I
  kept the command building next to the other git commands.

**Measured on the real fixture** (blobless mirror of `maormagori/aws-leak-fixture`, all 14 commits, counted with
`GIT_TRACE` lines `built-in: git fetch`): plain `git log -p` for all commits = **12 fetches**; `streamCommitDiffs`
with the prefetch = **1 fetch**.

**How to verify:** `npm run check` (139 tests pass). New: `test/git/blobPrefetch.test.ts` (parser: both sides,
zeros, submodules, dedup; missing lines) and `test/git/bloblessClone.test.ts` (bare remote with `allowFilter` +
`allowAnySHA1InWant`, 4 commits, one fake key, blobless mirror over `file://`; asserts the key's line and exactly 1
fetch, then 0 fetches on a second run). With the prefetch call commented out the test fails with `expected 2 to be 1`.
