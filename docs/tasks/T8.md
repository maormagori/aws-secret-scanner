# T8 — Two entry points (api, worker) and role-prefixed logs

**Goal:** Replace the single `src/index.ts` + `ROLE` switch with two entry points, one per container, sharing one
bootstrap module. Every log line is prefixed with its role. Target: about 15 minutes.
**Depends on:** T1–T7 (working tree). Read `CLAUDE.md`, current `src/index.ts`, `src/config.ts`, `src/logger.ts`.
**May change:** `src/index.ts` (delete), new `src/bootstrap.ts`, `src/apiMain.ts`, `src/workerMain.ts`,
`src/config.ts`, `src/logger.ts`, `test/config.test.ts`, `test/helpers/testConfig.ts`, `package.json` (scripts only),
`Dockerfile`, `docker-compose.yml`, `README.md`. Nothing else. Do not commit.
**Verify:** `npm run check`; `docker compose up --build` starts 1 api + 2 workers; logs show the prefixes.

## Shape
- `src/bootstrap.ts`
  - `export type AppRole = 'api' | 'worker'`.
  - `createAppContext(role: AppRole): Promise<AppContext>` — loads config, creates the logger for that role, creates
    `dataDir`, opens the DB, builds both repositories. `AppContext = { config, logger, db, scanRepository,
    findingRepository }`.
  - `handleShutdownSignals(context, stop: () => Promise<void>): void` — on SIGTERM/SIGINT: log, `await stop()`, close
    the DB, exit 0. The DB closes last because `stop()` still writes (releasing scans).
- `src/apiMain.ts`: context for `'api'` → scan service → server → `listen` → shutdown closes the server.
- `src/workerMain.ts`: context for `'worker'` → git client, runner, pool → `start` → shutdown calls `pool.stop()`.
- Each main file is short and reads top to bottom; no role `if`s anywhere.
- Config: remove `role` (and `ROLE`); the entry point decides the role.
- Logger: `createLogger(config, role)`. Every message is prefixed with the role, e.g. `[api] Started` /
  `[worker] Scan completed`, using pino's `msgPrefix` option, and the role is also a structured field (`base: { role }`).
- `package.json` scripts: `dev:api` (`tsx watch src/apiMain.ts`), `dev:worker` (`tsx watch src/workerMain.ts`),
  `start:api` / `start:worker` (`node dist/src/…Main.js`); remove `dev` and `start`.
- Dockerfile: no role env; default `CMD` = the api entry. Compose: `api` service runs `node dist/src/apiMain.js`,
  `worker` service runs `node dist/src/workerMain.js` (`command:`), remove `ROLE` env.
- README: run locally = two terminals (`npm run dev:api`, `npm run dev:worker`); docker unchanged; config table without
  `ROLE`. Mention the log prefix in one line.

## TL;DR (the worker fills this in when done)
**Asked to do:** Replace `src/index.ts` and its `ROLE` switch with one entry point per container (api, worker) that share a
bootstrap module, and put the role in front of every log message.
**How I did it:**
- `src/bootstrap.ts`: `AppRole`, `createAppContext(role)` (config, logger, data dir, DB, both repositories) and
  `handleShutdownSignals(context, stop)`, which closes the DB after `stop()` because the worker still writes while stopping.
- `src/apiMain.ts` / `src/workerMain.ts`: each reads top to bottom with no role `if`s; `src/index.ts` deleted.
- `src/logger.ts`: `createLogger(config, role)` with pino `msgPrefix: '[role] '` and `base: { role }`; `role`/`ROLE` removed
  from `src/config.ts`.
- `package.json`: `dev:api`, `dev:worker`, `start:api`, `start:worker` (no more `dev`/`start`). Dockerfile `CMD` is the api
  entry; each compose service sets `command:` and no longer sets `ROLE`. README updated (two terminals, log prefix, no `ROLE`).
**Decisions / tradeoffs:**
- `logger.ts` imports the `AppRole` type from `bootstrap.ts`, which imports `createLogger`. It is a type-only cycle, so
  nothing breaks at runtime, and it keeps `AppRole` where the brief puts it.
- With the orchestrator's approval I also changed one line in each of `test/scanner/scanRunner.test.ts` and
  `test/worker/workerPool.test.ts` (outside the brief's list) to `createLogger(config, 'worker')`.
- Host port 3000 was in use, so for the docker check I used a scratch override outside the repo (port 3100, compose project
  `t8check`). The repo's compose file is unchanged apart from the brief's edits.
