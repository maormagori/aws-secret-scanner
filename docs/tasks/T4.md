## Contracts

### `src/services/scanService.ts` — `createScanService({ scanRepository, findingRepository, now? }): ScanService`
Results are discriminated unions; the service never knows about HTTP.
- `createScan(rawRepoUrl)`: `parseRepoUrl` → `{kind:'invalid', reason}` | `{kind:'created', scan}` | `{kind:'existing', scan}`.
- `getScan(scanId)` → `Scan | undefined`; `listScans()` → `Scan[]`.
- `listFindings(scanId, cursor, limit)` → `{kind:'not_found'}` | `{kind:'page', findings, nextCursor: number | null}`.
  `nextCursor` = last id when the page is full, else null.
- `stopScan(scanId)`: `queued` → transition to `stopped` (no lease token); `cloning`/`scanning` → `requestStop` (the
  worker stops after its current page); otherwise `{kind:'invalid_state', status}`; unknown → `not_found`.
  Returns `{kind:'stopping' | 'stopped', scan}`.
- `resumeScan(scanId)`: `stopped`/`failed` → `queued` with `resetAttempts: true`; another active scan for the same
  repo makes the update hit the unique index → `{kind:'conflict'}`; other states → `invalid_state`.
- A `transitionScan` `'conflict'` (someone changed it first) → re-read and return `invalid_state` with the new status.

### `src/api/server.ts` — `createServer({ scanService, logger }): FastifyInstance`
Fastify with the injected pino logger. No listening here (the entry point calls `listen`).

### `src/api/scanRoutes.ts`
| Route | Success | Errors |
|---|---|---|
| `POST /scans` body `{repoUrl}` | 202 `{scan}` created, 200 `{scan}` existing | 400 invalid body / repo URL |
| `GET /scans` | 200 `{scans}` | |
| `GET /scans/:scanId` | 200 `{scan}` | 404 |
| `GET /scans/:scanId/findings?cursor=&limit=` | 200 `{findings, nextCursor}` | 400 bad query, 404 |
| `POST /scans/:scanId/stop` | 202 `{scan}` | 404, 409 |
| `POST /scans/:scanId/resume` | 202 `{scan}` | 404, 409 |
| `GET /health` | 200 `{status:'ok'}` | |
- Validate bodies, params and queries with Zod schemas in `src/api/apiSchemas.ts` (`safeParse` → 400). `limit` default
  100, max 500.
- The public scan shape (`toScanResponse`) hides lease internals: `scanId, repoUrl, status, progress:{scannedCommits,
  totalCommits}, attempt, stopRequested, error, createdAt, updatedAt, finishedAt`.
- Status codes from `http-status-codes`. Error bodies `{ error: <message> }` with messages as exported constants in
  `src/api/apiErrors.ts`, so tests assert the same constants.
- Route paths as constants (they're used in tests too).

## Tests (in-memory SQLite, `createTestConfig`, Fastify `inject`, no network)
- POST valid → 202; same repo again → 200 with the same `scanId`; invalid URL → 400.
- GET unknown → 404. Findings paging with `cursor` across two pages (insert findings with the repository).
- Stop a queued scan → `stopped`; stop a completed scan → 409. Resume a stopped scan → `queued`.

## TL;DR (the worker fills this in when done)
**Asked to do:** Build the scan service (create/dedupe, get, list, findings paging, stop, resume) and the Fastify API
that validates input with Zod and maps service outcomes to HTTP status codes.

**How I did it:**
- `src/services/scanService.ts`: every method returns a discriminated union (`invalid`/`created`/`existing`,
  `not_found`/`page`, `stopping`/`stopped`/`invalid_state`, `queued`/`conflict`/`invalid_state`). A `transitionScan`
  conflict or a failed `requestStop` re-reads the scan and returns `invalid_state` with its new status.
- `src/api/apiSchemas.ts`: body/params/query schemas (`limit` default 100, max 500) and `ScanResponseSchema` +
  `toScanResponse`, built with `ScanSchema.pick(...)` so no field is retyped.
- `src/api/scanRoutes.ts`: one handler per route: `safeParse` → 400, call the service, `switch` on `kind`.
  `src/api/apiErrors.ts` holds the error messages, `src/api/routePaths.ts` the paths and `withScanId(path, id)`.
- `src/api/server.ts`: `createServer` builds Fastify with the injected pino logger (`loggerInstance`), no `listen`.
- `fastify` added with `npm install fastify` (`package.json` + `package-lock.json`).

**Decisions / tradeoffs:**
- **Resume conflict detection:** `transitionScan` throws SQLite's unique-constraint error (errcode 2067) when the repo
  already has an active scan. The service catches only that code and returns `{kind:'conflict'}`, and rethrows
  anything else. The SQLite code ends up in the service because the repository (T1) doesn't turn it into a value. A
  cleaner fix later: have `transitionScan` return `'duplicate_active'`.
- Resume also clears `error` (`error: null`), so a requeued scan doesn't show the old failure.
- Error bodies are `{ error: <constant>, details?: <text> }`. `details` carries the Zod message, the repo URL reason
  or the current status. Tests check only the `error` constant.
- Resume outcome kind is `queued` (the brief didn't name it). Health lives in `scanRoutes.ts` as the table lists it.
- `createServer` assigns the pino logger to a `FastifyBaseLogger` variable so the app's type is the plain
  `FastifyInstance` (otherwise Fastify infers a pino-specific generic that doesn't match the return type).
- `:scanId` is any non-empty string, so a malformed id gets 404, not 400, as in the route table.

**How to verify:** `npx vitest run test/api test/services` (17 tests) and `npm run check`. At hand-off, typecheck
failed only in `src/git/gitClient.ts` (T2, still in progress). Lint is clean and all 86 tests pass.
