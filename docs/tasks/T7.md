## 1. Abort must stop the whole git process tree (Codex P1)
Today abort kills only the `git` process; its remote helper (`git-remote-https`) can keep the pipes open, so
`cloneMirror` never settles and shutdown / lease-loss cleanup can hang.
- Spawn git with `detached: true` (its own process group) and on abort kill the group: `process.kill(-child.pid,
  'SIGTERM')`, then `SIGKILL` after a short grace period (named constant, e.g. 2 s) if it hasn't exited.
- The promise / generator must settle once the process group is gone, not wait on the pipes.
- Test: a local HTTP server (node `http`) that accepts the connection and never answers; `cloneMirror` from
  `http://127.0.0.1:<port>/x.git` with an abort after ~100 ms must reject with a retryable `GitCommandError` within
  ~3 s.

## 2. Quoted file paths (Codex P2)
Git C-quotes paths with `"`, `\`, tabs, newlines or control characters even with `core.quotePath=false`:
`+++ "b/quote\"name.env"`. The parser must handle both forms.
- `src/git/quotedPath.ts`: `unquoteGitPath(raw: string): string` — strips the quotes and decodes `\"`, `\\`, `\t`,
  `\n`, `\r`, and octal byte escapes `\ooo` (collect bytes, decode as UTF-8).
- The diff parser uses it for `+++ ` lines; strip the `b/` prefix after unquoting.
- Tests: unit tests for `unquoteGitPath`; a real-git test committing the same fake key to `normal.env`,
  `quote"name.env` and a tab-containing name → three findings' paths come back decoded.

## TL;DR (the worker fills this in when done)
**Asked to do:** Make an abort stop git and its remote helper so `cloneMirror` always settles, and make the diff
parser read the C-quoted paths git writes for names with `"`, `\`, tabs, newlines or control characters.

**How I did it:**
- `src/git/gitProcess.ts` (new): `spawnGitProcess` spawns git with `detached: true` (its own process group).
  `kill()` does not depend on whether git itself has exited, because a helper can outlive it and keep stdout open
  (second Codex review). It always sends `SIGTERM` to the group (`process.kill(-pid)`, only `ESRCH` ignored). It closes
  our ends of stdout/stderr and the line reader at once, so `close` fires and the caller settles without waiting on
  helpers. It always sends `SIGKILL` to the group after `KILL_GRACE_PERIOD_MS` (2 s, unref'd timer). The abort listener
  stays until `kill()` runs or the streams close normally. `writeStdin` moved here too.
- `src/git/gitClient.ts`: `streamGitLines` now uses `spawnGitProcess`; the error mapping (killed → exit `null` →
  retryable `GitCommandError`) is unchanged. 191 → 176 lines.
- `src/git/quotedPath.ts` (new): `unquoteGitPath` works on the UTF-8 bytes of the quoted body, decodes `\ooo` octal
  bytes and the simple escapes, then decodes the bytes once as UTF-8.
- `src/git/diffParser.ts`: any `+++ ` line goes through `parseNewFilePath`: strip git's trailing tab, unquote, then
  strip `b/`. Anything without `b/` (`/dev/null`) gives no path, as before.

**Decisions / tradeoffs:**
- `unquoteGitPath` also decodes `\a \b \v \f`. The brief didn't list them, but git's `quote_c_style` writes them for
  those control characters, so without them a real repo could crash the scan. An escape git never writes throws.
- The `try/catch` around `process.kill(-pid)` ignores only `ESRCH` (the group is already gone, e.g. at the 2 s
  `SIGKILL`). Any other error is rethrown.
- A second `kill()` (abort, then the caller's `finally`) does nothing, and neither does `kill()` after a normal
  `close`. So a successful command never signals a process group that is already gone.
- After a kill, `waitForExit` reports `exitCode: null` even if git had already exited 0. Otherwise output we never
  read would pass as a complete, successful run (e.g. a batch of commits silently cut short).
- The line iterator is created when git is spawned. An iterator created after the reader closed (an already-aborted
  signal) never ends.
- `gitClient.ts` is still 176 lines (over the ~150 target). The rest is the auth/redaction helpers, which T7 doesn't
  allow moving to a new file.
- The real-git quoted-paths test resets `main` after its commit so other tests in the file still see the original refs.
