## `src/index.ts`
- `main()`: `loadConfig(process.env)`, `createLogger`, create `dataDir`, `openDatabase(config.databaseFile)`, both
  repositories. Then by `config.role`:
  - `api` or `all`: `createScanService`, `createServer`, `listen({ port: config.port, host: '0.0.0.0' })`.
  - `worker` or `all`: `createGitClient(config)`, `createScanRunner({... detectLeaks })`, `createWorkerPool(...).start()`.
- `SIGTERM`/`SIGINT`: close the server, `await pool.stop()` (releases running scans), close the DB, exit 0.
- Entry-point is the only place with top-level wiring; keep functions short (`startApi`, `startWorkers`).

## Docker
- `Dockerfile`, multi-stage: build stage `npm ci` + `npm run build`; runtime stage `node:24-alpine` with `git` installed,
  `npm ci --omit=dev`, the built `dist/`, non-root user, `CMD ["node", "dist/src/index.js"]` (check the real output
  path from `tsconfig.json`). `.dockerignore`: `node_modules`, `dist`, `data`, `.git`, `docs/*.pdf`.
- `docker-compose.yml`: service `api` (`ROLE=api`, port 3000) and service `worker` (`ROLE=worker`,
  `deploy.replicas: 2`). Both mount a named volume at `/data` with `DATABASE_FILE=/data/scanner.db`. Workers set
  `CLONES_DIR=/tmp/clones` (inside each container, not on the shared volume). `GITHUB_TOKEN: ${GITHUB_TOKEN:-}`.

## TL;DR (the worker fills this in when done)
**Asked to do:** Wire the entry point by role, containerize (one image, api + 2 workers), write the README, and run a
real scan of the fixture repo, including a kill and resume.
**How I did it:**
- `src/index.ts`: `main()` builds config, logger, DB and repositories, then `startApi` / `startWorkers` by `ROLE`.
  SIGTERM/SIGINT closes the server, `await pool.stop()`, closes the DB, exits 0. Deleted `test/smoke.test.ts`.
- `Dockerfile`: multi-stage, `node:24-alpine` + `git`, `npm ci --omit=dev`, non-root `node` user,
  `CMD ["node", "dist/src/index.js"]`. `.dockerignore` as briefed (+ `.vitest`).
- `docker-compose.yml`: `api` (port 3000) + `worker` (`replicas: 2`, `CLONES_DIR=/tmp/clones`), named volume at `/data`.
- `README.md`: run, curl examples, config table from `src/config.ts` (with the T6 names `MAX_DELIVERIES` /
  `deliveryCount`), how it works, limits. `package.json`: `start` script.
**Decisions / tradeoffs:**
- The Dockerfile pins npm to 11.6.2 (the version that wrote `package-lock.json`). npm 11.19.1 in `node:24-alpine`
  rejects the lockfile (`Missing: @emnapi/core@2.0.0-beta.2`, optional deps of the wasm32 rolldown binding).
  Regenerating the lockfile would rewrite ~3,000 lines, so I pinned npm instead. Alternative: someone fixes the lockfile.
- Compose uses `GITHUB_TOKEN:` (pass-through, no value) instead of `${GITHUB_TOKEN:-}`. The empty-string form made every
  clone fail: config accepts `""` and the git client sends it as a token (and redacts `""` between every character).
- Compose also sets `DATA_DIR=/data` so the directory the entry point creates is the volume.
**Findings vs EXPECTED_FINDINGS.md (end-to-end, `ROLE=all`, and again in Docker; both 19 findings, identical):**
- Must-be-found rows 1–10: all found, in that order, with matching commit, committer, file, line, type and value.
- The repeated access key ids in `EXPECTED_FINDINGS.md` (commit ebd92c8): all 7 found (lines 10, 12, 14, 15, 17, 19, 35).
- Must-not-be-found: none reported, except as below.
- **Mismatch (2 extra findings):** `EXPECTED_FINDINGS.md` line 18 (table row 9) reports two `aws_secret_access_key`
  values: `27de6e3aefa563a013c264ccb33a317520ed8608` (a commit SHA) and `wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY`.
  Cause: `SECRET_KEYWORD_PATTERN` in `src/scanner/detector.ts` (`aws.{0,20}secret`) matches `aws.env | 3 | secret`.
  The fixture says secrets in that file must not be reported. Not fixed (out of my files).
- Also found (not my files): an empty `GITHUB_TOKEN` is treated as a token (`src/config.ts` / `src/git/gitClient.ts`).
**Resume after kill:** `BATCH_SIZE=1`, `LEASE_MS=3000`; `kill -9` at 3/14 commits (status `scanning`, 11 findings, clone
dir left). After restart, the leftover clone dir was wiped, the scan was reclaimed and completed 14/14. Final findings
are identical to the uninterrupted run, in the same order, with no duplicates.

commands. Local: `ROLE=all DATA_DIR=… DATABASE_FILE=… CLONES_DIR=… npm run dev`.
